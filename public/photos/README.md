# 植物照片規格　PHOTO SPEC

驗證與前端共用的影像規格。補圖前請先看這份。

---

## 一、檔名與槽位

```
public/photos/<植物中文名><槽位>.jpg
```

| 槽位 | 檔名範例 | 內容 | 重要性 |
|---|---|---|---|
| `_habit` | `野牡丹_habit.jpg` | **全株／群落尺度** | ★ 驗證優先讀這個 |
| `_close` | `野牡丹_close.jpg` | 枝條中間尺度（花序、果序連枝葉） | 次要 |
| `_leaf` | `野牡丹_leaf.jpg` | 葉形特寫 | 次要 |
| 無後綴 | `野牡丹.jpg` | 代表圖（前端主圖備援） | 備援 |

驗證腳本的讀取順序為 `_habit` → `_close` → 無後綴 → `_leaf`，
因此 **`_habit` 這一張決定了 S_llm 效標的品質**，優先補齊。

---

## 二、像素規格

| 項目 | 規格 | 理由 |
|---|---|---|
| **長邊像素** | **1200–1600 px**（最佳 1568） | Anthropic Vision 會把長邊縮到 1568 px；超過只是浪費檔案大小 |
| 長邊下限 | 800 px | 驗證腳本會縮到 768 px，原圖低於 800 px 會糊掉 |
| 短邊下限 | 600 px | 前端切正方形縮圖用 |
| **長寬比** | 4:3 / 3:2 / 1:1 | 前端 `object-fit: cover` 會裁成正方形 |
| 避免 | 16:9 全景、9:16 直幅 | 裁切後兩側主體會被切掉 |
| **檔案大小** | **< 2 MB**（硬上限 5 MB） | 5 MB 為 Vision API 單張上限，現有 `燈稱花.jpg` 已達 5.3 MB 超標 |
| 格式 | JPEG（`.jpg`）、sRGB | 前端與腳本皆以 `.jpg` 尋檔 |
| 品質 | JPEG q85 左右 | 1600 px q85 約 300–600 KB |

**不要放大插補**：800 px 的原圖拉到 1600 px 不會增加資訊，反而讓 VLM 判讀變差。原圖多大就交多大（在上限內）。

**主體置中**：前端裁正方形是從中央裁，主體偏在畫面邊緣會被切掉。

## 三、內容標準

### `_habit` 全株照必須做到

- 看得出**高度、展幅、分枝方式、整體質地**（這四項正是 S_attr 在比的東西）
- 自然生長狀態，**不要修剪造型**（球形、方形綠籬皆不可）
- 單一植株完整入鏡，或成片群落

### 一律排除

- 畫面中有**人工物**：解說牌、建築、鋪面、柵欄、盆器、標籤
- 畫面中有**動物或昆蟲**占顯著面積（蝴蝶、蛾、鳥）
- **非攝影影像**：植物版畫、插畫、標本掃描
- 純色棚拍背景（黑底、白底）的花朵特寫 — 這類只能放 `_close`，不能放 `_habit`
- 物種辨識存疑者

## 四、稽核紀錄

2026-08-04 逐張目視稽核 25 張，結果：僅 3 張（蠅翼草、麥門冬、黃荊）符合 `_habit` 標準。
詳見 `validation/植徑v3_附錄B_S_attr_S_llm_驗證結果報告.pdf` §4.2。

已知不合格且列入驗證黑名單（`scripts/validate-similarity.mjs` 的 `BAD_PHOTOS`）：

| 物種 | 問題 |
|---|---|
| 青葙 | 主體為鳥類（Lilac-breasted Roller） |
| 綬草 | 古典植物版畫，非攝影 |
| 絡石 | 蛾占畫面顯著面積 |
| 田代氏石斑木 | 住宅街景中的修剪球形灌木 |

補上合格照片後，請自 `BAD_PHOTOS` 移除對應項目再重跑驗證。

## 五、交件前自檢

```bash
# 檢查尺寸與檔案大小
cd public/photos && identify -format "%f  %wx%h  %[size]\n" *_habit.jpg

# 批次壓到規格內（原地覆蓋前請先備份）
mogrify -resize 1568x1568\> -quality 85 *.jpg
```
